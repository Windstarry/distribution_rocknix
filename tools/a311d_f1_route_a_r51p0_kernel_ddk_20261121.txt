三、Linux 6.18 兼容补丁内容（逐项均由真实编译错误驱动，非猜测）
--------------------------------------------------------------------------------
目标内核：A311D 用 6.18.49（linux/package.mk 单独 case），S922X 用 6.18.21；
补丁以 KERNEL_VERSION(6,18,0) 为闸门，对 6.12 等其他内核无影响。

3.1 Kbuild（src 路径）：6.18 改变 out-of-tree 的 $(src) 解析，原公式拼出
    /work/linux-6.18.49/././arbiter/Kbuild（内核树而非模块树）导致
    "No rule to make target"。改为优先用 $(KBUILD_EXTMOD) 作绝对基准。
3.2 mali_kbase_core_linux.c：
    - platform_driver.remove 在 6.18 是 void(*)，原 int 函数签名不兼容；
      改为 static void，删掉 if(!kbdev)return -ENODEV 与尾部 return 0。
    - FMODE_UNSIGNED_OFFSET 已移除，删除该赋值行。
3.3 mali_kbase_mem_migrate.c：page migration API 在 6.18 更名：
    - __SetPageMovable(p,&ops) → SetPageMovableOps(p)（6 处）
    - __ClearPageMovable() 全部删除：6.18 明确 PG_movable_ops 只能由内核
      free 时清除，驱动不得清除（page-flags.h 注释原文）。
3.4 mali_kbase_fence_ops.c：dma_fence_ops.fence_value_str 回调在 6.18 移除；
    两处初始化删除，结构体正确闭合。
3.5 device/mali_kbase_device.c：dma_set_max_seg_size 在 6.18 返回 void；
    去掉 `err = ` 赋值（原 err=void 报 "void value not ignored"）。
3.6 version_compat_defs.h（末尾追加 shim，KERNEL_VERSION>=6.18 闸门）：
    - hrtimer_init → hrtimer_setup(t,NULL,clock,mode)（源码随后手动赋
      timer->function，编译验证语义等价）
    - hrtimer_init_on_stack → hrtimer_setup_on_stack(t,NULL,...)
    - del_timer → timer_delete；del_timer_sync → timer_delete_sync
    - no_llseek → noop_llseek（无版本闸门，仅当未定义时生效）

四、真实交叉编译验证（决定性证据）
--------------------------------------------------------------------------------
4.1 环境：Docker mali-verify:trixie（Debian trixie + aarch64-linux-gnu-gcc
    14.2），源码 Linux 6.18.49 完整树 + ARM r51p0 DDK，ARCH=arm64。
4.2 过程：从 pristine tar 解包 → apply_618.sh 应用补丁 → kernel make 编译
    CONFIG_MALI_MIDGARD=m CONFIG_MALI_PLATFORM_NAME=meson CONFIG_MALI_REAL_HW=y
    CONFIG_MALI_DEVFREQ=y CONFIG_MALI_GATOR_SUPPORT=y。
4.3 逐轮修正共解决 12 类 6.18 API 不兼容（Kbuild 路径、remove 签名、
    FMODE、PageMovable×2、fence_value_str、dma_set_max_seg_size、
    hrtimer_init、hrtimer_init_on_stack、del_timer、del_timer_sync、no_llseek）。
4.4 结果：BUILD_OK，114 个 .o，产出 mali_kbase.ko 6.8 MiB。
4.5 从产出的 ko 实测版本串：
    version=r51p0-00eac0 (UK version 11.48)
    → 与用户态 Bifrost-r51p0-00eac0 完全配平（对比原镜像 r54p2-02eac0 UK11.46）。
4.6 说明：验证末段 modpost 因 modules_prepare 无完整 Module.symvers 报

    kernel_make 先完整编内核再编外部模块，不存在该问题。
