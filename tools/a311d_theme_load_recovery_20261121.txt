一、目标与结论
--------------------------------------------------------------------------------
目标：先让前端主题渲染出来（用户接受暂时牺牲 GPU 加速），不追求 libmali
      本身的可用性。
结论 [板级实证]：已达成。把 gpu.driver 从 libmali 切回 panfrost 并重启后，
      EmulationStation 主题（art-book-next）完整加载、中文提示栏清晰、
      无绿屏、无缺字；GPU fault 计数由 2056 归零。切换前的配置已备份，
      可随时回滚。

说明：先前报告的「panfrost 绿屏」现象在本轮未复现。本轮实证为「当前这块
      盘 + 20261113 镜像 + panfrost」组合下主题正常且无绿屏；
      绿屏的触发条件仍未定性，不得据此写「panfrost 绿屏已修复」。

二、为什么走 panfrost（而不是继续修 libmali 或走软件渲染）
--------------------------------------------------------------------------------
1. libmali 支已被实证为 DDK 硬不匹配：内核 mali_kbase r54p2-02eac0 对
   libmali.so.1.9.0 内嵌 r51p0-00eac0，2056 次 GPU fault 0x51
   INSTR_INVALID_ENC，且 ES 硬链接 libmali-hook.so.1（DT_NEEDED，
   纯转发到 libmali.so.1，无软件回退），环境变量无法绕开。
   → 版本配平需重建 libmali 或内核，不是「先让主题加载」的快捷路径。
2. Mesa 软件渲染（swrast/llvmpipe）看似可选（libEGL_mesa.so.0.0.0、
   libdril_dri.so 均在盘），但 libEGL.so.1.1.0 / libGLESv2.so.2.1.0
   被 /dev/loop0 bind mount 成 libmali 垫片，且 ES 直接链接 libmali-hook，
   只靠 LIBGL_ALWAYS_SOFTWARE 之类变量无法让 ES 改走 Mesa。
3. panfrost 是双栈方案 v2 的阶段 1 基线，回退路径明确（改回设置 + 重启），
   切换机制 gpudriver --start 已在原镜像验证过。
   → 选它作为「先让主题加载」的最短路径。

四、执行步骤（可回滚）
--------------------------------------------------------------------------------
  1. 备份：
     mkdir -p /storage/_gpu_backup
     cp -a /storage/.config/system/configs/system.cfg \
           /storage/_gpu_backup/system.cfg.before-panfrost
     （备份文件 9019 B，mtime 01:13）
  2. 改设置：
     sed -i 's/^gpu.driver=.*/gpu.driver=panfrost/' \
           /storage/.config/system/configs/system.cfg
     → 112:gpu.driver=panfrost；sync
  3. 冷启动：
     systemctl reboot --no-block；18 s 后 SSH 断开，32 s 后恢复
  4. gpudriver --start 在启动时自动完成：
     modprobe -r mali_kbase；modprobe panfrost；
     umount libmali 的 libEGL/libGLES/libgbm bind mounts；
     恢复 libGL 与 panfrost Vulkan ICD、屏蔽 mali.json
