一、结论摘要
--------------------------------------------------------------------------------
1. A311D 的 linux 包 PKG_VERSION 已由 6.18.21 单独对齐到 6.18.49，
   S922X / RK3399 / RK3566 保持 6.18.21 不变（原四设备共用 case 已拆分）。
   [实证-源码]

2. 【本轮最关键发现】只改版本号不足以让镜像可引导。A311D 的
   linux.aarch64.conf 原本写着 "# CONFIG_SCSI is not set"，且没有
   CONFIG_BLK_DEV_SD / CONFIG_USB_STORAGE。6.18.49 源码的
   drivers/usb/storage/Kconfig 明确 "USB_STORAGE depends on SCSI"，
   Help 还要求 BLK_DEV_SD。这条链缺失，USB U 盘枚举成功却永远不产生
   sdX，initramfs 自然找不到 LABEL=ROCKNIX。这与 11-10/11-11 失败串口
   日志（枚举到 048d:1234、之后无 usb-storage / scsi host / sdX）
   以及实验 A 的活体 dmesg 完全自洽。[实证-源码 + 实证-活体]

   因此本次同步补齐 CONFIG_SCSI=y / CONFIG_BLK_DEV_SD=y /
   CONFIG_USB_STORAGE=y。这是「引导 + GPU 栈在同一次变更中恢复可用」
   的必要条件，不是无关配置调整。

3. 5 个 mainline 补丁经 6.18.21 与 6.18.49 双版本 dry-run 全部可应用，
   无需改动；构建系统对普通文本补丁实际使用 patch -p1（允许 fuzz），
   不是 git apply。[实证-源码]

4. 目标磁盘变更场景（三分区、P3=0x07 显示 NTFS、未格式化、无盘符）
   的错误原因判定与提示内容已在 tools/a311d_games_partition_check.py
   中修正，仅该场景新增 TC-GP-07 / TC-GP-08，其它布局零新增项。
   [实证-离线单元验证]

5. [不得写]「已修复」「重建完成」「设备已验证引导」「panfrost.ko
   已加载」「renderD128 已出现」「GPU 栈正常」。

2.4 tools/a311d_games_partition_check.py（用户本次追加需求）
  a) docstring 增补「目标磁盘变更后三分区」场景定义。
  b) import string（标准库，无新依赖）。
  c) check_volume 两处失败提示改写：
     - 打不开卷时补充「F: 可能是 P1(FAT32 boot)，未格式化的
       0x07 P3 没有盘符」；
     - 无 EXFAT 签名时不再笼统写「volume is not exFAT」，
       改为「该盘符可能是 P1，P3 为 0x07/NTFS 标签、
       未格式化、无盘符」。
     判定逻辑（PASS if bpb else FAIL）不变。
  d) 新增 list_exfat_letters()（只读枚举）与
     check_target_disk_change()：仅当「恰好三个非空分区 +
     P3=0x07 且 size>0 + 指定卷不是 exFAT + 给了 --disk」时，
     输出 TC-GP-07（原因判定：0x07 是 IFS/NTFS/exFAT 共用
     类型标签，不是真 NTFS；mkfs.exfat 未完成导致未格式化、
     Windows 不分配盘符；F: 指向 P1 而非 P3）与
     TC-GP-08（提示内容：查 fs-resize.log、不要套用 5.12
     FAT32 类型错误、不要真格式化成 NTFS、不要归因 RAW 缓存）。
  e) main() 接收 check_mbr 的返回值并调用新判定，其余流程不变。

2.5 tools/a311d_runbook.txt
  保留原 5.12（0x0c FAT32 类型错误的历史场景）不动，

3.2 真实源码取证 [实证]
  从清华镜像下载完整内核 tarball：
    linux-6.18.49.tar.xz  154,627,808 B（kernel.org HEAD 亦为 200）
    linux-6.18.21.tar.xz  154,425,436 B
  按构建系统 scripts/unpack 的实际方式做双版本 dry-run：
    patch -p1 --dry-run（普通文本补丁走 scripts/unpack:196；
    只有含 GIT binary patch / rename from / rename to 的补丁才走
    scripts/unpack:194 的 git apply）
    版本      0001  0002  0003  0004  0005
    6.18.21   RC=0  RC=0  RC=0  RC=0  RC=0
    6.18.49   RC=0  RC=0  RC=0  RC=0  RC=0
    两版本行为完全一致：0002 的 drivers/input/Makefile hunk
    各需 fuzz 1，其余零 fuzz。结论：补丁无需改动，其它平台不受影响。
  注：曾额外用 git apply --check 验证，0002 在该路径下会因
  drivers/input/Makefile 的 "touchscreen.o touch-overlay.o" 上下文
  失败；但该路径不适用于本仓库的普通文本补丁，故不作为判据，
  也未据此修改补丁。

3.3 配置项核查 [实证]
  解析 6.18.49 源码 1880 个 Kconfig* 文件，共 21,394 个符号；
  A311D conf 有 5,286 个 CONFIG_ 符号。
  - conf 中「源码无 Kconfig 定义」仅 3 个：CHARGER_RK818、
    INPUT_ADC_KEYS、INPUT_POLLDEV；后两个由 mainline 补丁的
    Kconfig hunk 提供，属未打补丁源码的假阳性，CHARGER_RK818
    是 Rockchip 残留，oldconfig 会丢弃，均无影响。
  - 关键项在 conf 与 6.18.49 源码中均存在：
    DRM_PANFROST / DRM_MESON / SCSI / EXFAT_FS / NTFS3_FS。
  - 6.18.49 drivers/usb/storage/Kconfig 原文：
      config USB_STORAGE  tristate ...  depends on SCSI
      "you probably also need ... (BLK_DEV_SD)"
    -> 补齐三项后依赖链闭合。
  - A311D conf 已具备 USB 主机侧全部要件（USB_DWC3=y、
    USB_DWC3_MESON_G12A=y、XHCI/EHCI/OHCI、PHY_MESON_G12A_*），
    与失败日志「能枚举 USB 设备」一致，缺的只是存储绑定链。
  同项目 RK3566 conf 作对照：SCSI=y / SCSI_PROC_FS=y /
  BLK_DEV_SD=y / USB_STORAGE=y。

3.4 分区判定离线单元验证 [实证]
  构造 6 组输入，检查新增判定的触发范围：
    三分区 + P3=0x07 + 卷非 exFAT        -> TC-GP-07 FAIL + TC-GP-08 NOTE
    两分区                                -> 零新增项
    P3=0x0c（5.12 历史场景）             -> 零新增项
    P3=0x07 但卷已是 exFAT               -> 零新增项
    未给 --disk（parts=None）             -> 零新增项
    四个非空分区                          -> 零新增项
  真实只读运行 --volume F:：首扇区 eb58906d6b66732e666174
  = "mkfs.fat"（FAT32 P1），提示已指向 P1/P3 场景；
  未给 --disk 时不产生 TC-GP-07/08，符合预期。
  本机只读扫描另见 G: 为 FAT32、H: 为 EXFAT、物理盘 MBR 因
  无管理员权限读不到；这些属于其它磁盘，判定逻辑未受影响。

3.5 KERNEL/SYSTEM 同源机制 [实证-源码]
  package.mk 第 156 行把 ${PKG_VERSION} 写入 .scmversion；
  第 623/626 行 kernel_make ... modules_install 把同一
  ${PKG_BUILD} 源码树产出的模块装到
  ${INSTALL}/$(get_kernel_overlay_dir)。因此 KERNEL 与 SYSTEM
  模块目录版本由同一个 PKG_VERSION 单点驱动，对齐后天然同源，
  不再出现 6.18.49 内核配 6.18.21 模块的版本混刷。
