三、决定性结论（三次修正后的最终版）

3.1 原任务前提不成立
最初判断「mali_kbase 内核模块与 libmali 用户态未一起打包」。2026-11-09
23:58 的 AURKNIX 实机复核证明两者本来就在 SYSTEM 里：
  /usr/lib/kernel-overlays/base/lib/modules/6.18.21/mali-bifrost/mali_kbase.ko
  /usr/lib/kernel-overlays/base/lib/modules/6.18.21/kernel/drivers/gpu/drm/panfrost/panfrost.ko
  /usr/lib/mali                     （10-31 00:35，131,849 字节，5 组库）
  /usr/lib/libEGL_mesa.so.0.0.0
  modules.dep 内两条模块记录均存在
因此「把两个组件打包」无需再做，重复实现没有意义。

3.2 真正的首要根因：KERNEL 与 SYSTEM 版本错配
运行内核 6.18.49（11-08 20:02 构建，来自现网 ROCKNIX），而 SYSTEM 是
10-31 构建（OS_VERSION=20261031），模块 vermagic 为
「6.18.21 SMP preempt mod_unload aarch64」。结果：
  /lib/modules/6.18.49 与 /usr/lib/modules/6.18.49 均为空目录、无 modules.dep
  modprobe -n -v panfrost -> FATAL: Module panfrost not found in directory /lib/modules/6.18.49
  autostart 日志同时报 panfrost not found / mali_kbase not found
  lsmod 无任何 GPU 模块；/dev/dri 只有 card0 (ff900000.vpu)，
  没有 card1 (ffe40000.gpu) 与 renderD128；无 /dev/mali*
  ES 反复重启，报 No mali devices found / Could not initialize EGL
vermagic 不匹配，把 6.18.21 目录软链到 6.18.49 也会被内核拒绝，
临时绕过不可行。此前尝试 LD_PRELOAD、LD_LIBRARY_PATH overlay、
SDL_VIDEO_GL_DRIVER 全部无效，原因是缺内核驱动创建的设备节点，
不是用户态库路径问题。

3.3 默认 GPU 栈必须是 panfrost，不是 libmali
对照组：现网 ROCKNIX 20261108（next，BUILD_ID 0b991b0e...，
HW_DEVICE=S922X-BOX，内核 6.18.49）能正常进前端，实际加载的是
panfrost + Mesa（ES 进程映射 libEGL_mesa.so.0.0.0 / libgbm.so.1.0.0，
/dev/dri/card1 + renderD128 正常，无 /dev/mali*）。
决定性实验：操作者把该现网系统手动切为 libmali 后，前端同样起不来
并需换回 AURKNIX。同一台设备、同一份 DTB，仅切换 GPU 栈即可复现。
原因：实机 DTB 只有 gpu@ffe40000（arm,mali-bifrost，okay），没有
arm,mali-midgard 厂商 DDK 节点，libmali 找不到设备。
差异点落在配置层：现网 /usr/config/system/configs/system.cfg:227
为 gpu.driver=panfrost；本仓库同文件 321 行全文无 gpu 行，
gpudriver 缺省回落 libmali。

3.4 UI_SERVICE 缺口
/usr/bin/autostart 结尾执行 systemctl start ${UI_SERVICE}。
本仓库 platforms/A311D 目录不存在，SYSTEM 的 /etc/profile.d 也无赋值，
导致 systemctl[1695]: Too few arguments。
现网由 platforms/S922X-BOX/090-ui_service 写入
UI_SERVICE="sway.service essway.service"。
AURKNIX 实机当前只解析到 essway.service，来源是上一轮调试残留的
/storage/.config/profile.d/999-ui-service，缺少 sway.service。

3.5 DTB 不是差异原因
现网与 AURKNIX 的 /flash/dtb.img 均为 54,984 字节、
md5 0fee9ffd2a2f3cb4a891b71176e3ee6a，与本地
E:\A311d\AURKNIX-image-A311D-20261031\ 下 bootsafe / edidmode /
S922X_ref 三份 DTB 字节级一致。

3.6 已排除项
rocknix-report-stats.service 本次 Result=success、job 已结束，不是前端
未起的原因；ASoC dpcm_fe_dai_open() 告警已过；meson DRM user-defined
mode 问题已由 video=HDMI-A-1:D 修复；GAMES 分区已手动格式化为
MBR 0x07 + exFAT 并可用。

四、本轮已落地的仓库改动（6 个文件）

4.1 新建 projects/ROCKNIX/devices/A311D/filesystem/etc/profile.d/090-ui_service
SYSTEM 层默认 UI_SERVICE="sway.service essway.service"。
scripts/image:190-191 会把 devices/<DEVICE>/filesystem/* 拷进 SYSTEM 根。
rocknix-autostart.service 以 bash -a -c 'source /etc/profile && exec
/usr/bin/autostart' 启动，且 autostart 在 systemctl start 之前再次
source /etc/profile，因此该文件每次启动都会被读取。

4.2 新建 projects/ROCKNIX/packages/hardware/quirks/platforms/A311D/090-ui_service
平台 quirk，用户层兜底。autostart 用 HW_DEVICE（scripts/image:163
设为 DEVICE，即 A311D）定位 platforms/<HW_DEVICE> 并在早期执行；
quirks/package.mk:22-25 只拷贝当前平台的目录。
除写入规范的 090-ui_service 外，还会幂等清理上一轮调试残留
/storage/.config/profile.d/999-ui-service。必须清理的原因：
/etc/profile 先 source /etc/profile.d/*，后 source
/storage/.config/profile.d/*，999- 前缀排在最后，会把 UI_SERVICE
覆盖成只有 essway.service。

4.3 修改 projects/ROCKNIX/packages/rocknix/package.mk
在 makeinstall_target() 内按 DEVICE=A311D 条件，向 SYSTEM 的
/usr/config/system/configs/system.cfg 注入或改写 gpu.driver=panfrost。
不改共享默认值，其它设备不受影响。get_setting() 只读用户层
/storage/.config/system/configs/system.cfg，该文件在首次启动时由
001-functions:set_setting / post-update 从 SYSTEM 默认种子复制。

4.4 修改 projects/ROCKNIX/packages/graphics/gpudriver/sources/bin/gpu-dtb
附加防护。plan-rocknix-a311d.md 的 P3 计划里 dtb-panfrost.img 从未
产出，而 gpudriver panfrost 会调用 gpu-dtb set panfrost，把
gpu_dtb=dtb-panfrost.img 写进 /flash/config.ini；Generic_cfgload.src:23
会据此 fatload 一个不存在的文件，下次启动有黑屏风险。
现改为：目标 DTB 不存在且请求 panfrost 时回落 dtb.img（该 DTB 已被
现网验证可驱动 panfrost/Mesa），否则不写 config.ini 并退出 1。

4.5 新建 tools/a311d_gpu_stack_check.py
只读一致性校验工具（Python 标准库，18 项检查）。
离线 SYSTEM 检查 TC-SYS-01..10：UI_SERVICE、gpu.driver、A311D quirk、
gpudriver 占位符、模块目录唯一性、panfrost.ko、mali_kbase.ko、
libmali 用户态、modules.dep、vermagic 与目录版本一致性。
实机检查 TC-LIVE-01..08：uname -r 与模块目录一致、modules.dep 存在、
panfrost 已加载、card1/renderD 存在、gpu.driver、UI_SERVICE、
sway/essway active 且 NRestarts 低、gpu_dtb 无悬空引用。
支持 --list-checks / --probe-command / --root / --live / --json。
退出码 0=无 FAIL，1=有 FAIL，2=用法或 IO 错误。

补记四（2026-11-10）：纠正"本机实测只能 panfrost"归因 + 镜像未吃到 DTS 修复的构建断链
================================================================================
1. 纠正错误归因
   此前补记三 2.3 与第三节 3.3 以"本机实测只能用 panfrost 起前端 / libmali
   找不到设备（缺 midgard 节点）"作为硬件结论，此归因错误，现纠正：
   - A311D 为 Bifrost G52。panfrost(Mesa) 与厂商 Mali DDK（mali_kbase.ko +
     libmali）绑的是**同一个** arm,mali-bifrost 节点；libmali 原生支持
     Bifrost。所谓"libmali 找不到设备"系误判——真正缺失的是 midgard 节点，
     而 midgard 本就不该出现在 A311D 上（那是给 T 系列老 GPU 的架构）。
   - 现网把 GPU 栈由 panfrost 切到 libmali 后前端起不来，只证明"那次切换
     未成功"，不能证明"硬件只能用 panfrost"。失败根因尚未查清（gpudriver
     libmali 路径 / mali_kbase 加载 / EGL 绑定 / 与已绑定 panfrost 的冲突
     等），需要实机日志，此前 SSH 掉线未取到。属待诊断的软件问题。

2. 仓库 DTS 翻转方向仍正确，且与"libmali 是否可用"无关
   &mali(bifrost) 必须 enabled：这是 panfrost 与 libmali 两者都需要的
   先决条件（mali_kbase 同样 probe arm,mali-bifrost）。mali_vulkan
   (arm,mali-midgard) 节点对 A311D 是错架构，disabled 正确。故翻转没有
   "关掉 libmali"，反而让 libmali 更可能工作。DTS 头部与 &mali 注释已同步
   去掉"本板只能 panfrost"的错误表述。

3. 新发现：20261110 镜像 dtb.img 根本没吃到 DTS 修复（构建断链）
   用正确实现的 FDT 解析器（tools/a311d_dtb_inspect.py）复核，20261110 镜像
   内 dtb.img(80,688B) 仍为：
     /soc/gpu@ffe40000 (arm,mali-bifrost) -> status=disabled
     /gpu_mali_vulkan@ffe40000 (arm,mali-midgard) -> status=okay
   与翻转后的仓库 DTS（bifrost okay / midgard disabled）恰好相反。
   构建链路已坐实：
     linux/package.mk 编译
       devices/A311D/linux/dts/amlogic/meson-g12b-a311d-cainiao-cniot-core.dts
       -> meson-g12b-a311d-cainiao-cniot-core.dtb
       -> usr/share/bootloader/device_trees/
     devices/A311D/bootloader/release 复制为 dtb.img
     bootloader/mkimage: mkimage_aml_boot 写入镜像启动分区
   因此 dtb.img 确实来自我改的 DTS；镜像仍是旧状态说明：该镜像在含翻转
   提交（708c46093e）的工作树之外构建（构建机未拉到该提交，或内核 .dtb
   被缓存未重编）。结论：这张镜像**不能直接刷**——其 bifrost 节点 disabled，
   任一 GPU 栈都绑不上设备，前端起不来。
