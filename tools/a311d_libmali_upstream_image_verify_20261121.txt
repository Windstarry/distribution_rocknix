--------------------------------------------------------------------------------

    P2  type=0x83 (ext4)       偏移 2164260864  大小 32 MiB，卷标 STORAGE

四、切换机制：镜像内 /usr/bin/gpudriver 实测原文要点
--------------------------------------------------------------------------------
4.1 配置键 gpu.driver；get_current_driver() 在为空时默认写入 libmali（# DEFAULT）。
4.2 --options 输出："panfrost libmali"。
4.3 load_driver libmali：
    - modprobe -r panfrost；modprobe mali_kbase
    - mount --bind 将 /usr/lib/mali/* 逐个覆盖到 /usr/lib/ 同名文件
      （命令形态：find /usr/{lib,lib32}/mali -type f -exec bash -c
        'lib={}; mount --bind $lib ${lib/\/mali\//\/}' ';'）
    - 若有 /usr/lib/glesonly 则同样覆盖 /usr/lib/libSDL2*
    - mount --bind /dev/null /usr/lib/libGL.so 与 /usr/lib32/libGL.so（屏蔽桌面 GL）
    - 对每个 panfrost ICD 执行 mount --bind /dev/null 屏蔽，保证 Vulkan 只见到 mali
4.4 load_driver panfrost：反向 umount 上述 bind、恢复 libGL、解屏蔽 panfrost ICD、
    屏蔽 mali.json；modprobe -r mali_kbase；modprobe panfrost。
4.5 显式切换命令会改配置并写 DTB overlay：
    gpudriver libmali  -> dtb_overlay set driver-gpu None
    gpudriver panfrost -> dtb_overlay set driver-gpu driver-gpu-panfrost.dtbo
    /usr/bin/dtb_overlay 实测存在（4,144 B）。
4.6 结论：镜像里的 libmali 不是"编译进系统的默认 GL"，而是"与 panfrost 并存、
    由用户态脚本用 mount bind + modprobe + ICD 屏蔽在运行期选定的一套用户态 blob+内核模块"。

五、决定性发现：DDK 版本不配平（本轮新增铁证）
--------------------------------------------------------------------------------
5.1 镜像内 mali_kbase.ko 的可打印字符串实测：
    version=r54p2-02eac0 (UK version 11.46)
    K:r54p2-02eac0(GPL)
    srcversion=7F9924119D95EDD64CFD158
    vermagic=7.2.11 SMP preempt mod_unload aarch64
    构建路径串：.../build.ROCKNIX-S922X.aarch64/build/
        mali-bifrost-39da994bb6fc8819e5e8c1873907dd21d17e53c1/...
5.2 用户态 libmali 为 r51p0（第 3.1 节文件名实证）。
5.3 因此该官方 20261101 S922X 镜像出厂即存在：用户态 r51p0 + 内核态 r54p2 的
    跨 DDK 组合。这与 2026-11-21 在 A311D 实机观测到的 "GPU fault 0x51
    INSTR_INVALID_ENC"（189s~779s，2,056 次）以及 libmali 卡"载入中"完全同源：
    内核 kbase r54p2 的指令编码/API 与 r51p0 用户 blob 不一致，GPU 执行非法指令。
5.4 注意：构建路径里的 39da994bb... 是上游 mali-bifrost 包中 RK3326/RK3566
    使用的 PKG_VERSION，S922X/A311D 在无专门 case 时落入默认分支复用它；
    上游并未为 S922X 固定 r51p0 内核 DDK。这是版本漂移的结构性来源。

六、镜像（上游 next 原版）与本地 a311d 分支的差异
--------------------------------------------------------------------------------
6.1 镜像内 gpudriver 为上游原版：DTB 切换用 /usr/bin/dtb_overlay、
    if [ -z ${CONFDRIVER} ] 未加引号、无 A311D 特例、无 mask_file/unmask_file
    对称处理、对 /usr/lib32/libGL.so 无条件 bind（不判断文件是否存在）。
6.2 本地 a311d 分支（HEAD d63745c717）gpudriver 已改造：
    - A311D case 的 DTB_OVERLAY_LOAD/UNLOAD 置空（chain-boot 无 extlinux/dtbo，
      切换仅记录设置、下次启动生效，不热切换运行栈）
    - 增加 is_masked/mask_file/unmask_file、Vulkan ICD 双向对称恢复
    - libGL 屏蔽改为逐路径判断存在且未屏蔽，避免重复 --start 叠加 bind
    两者用途不同：镜像是 S922X（extlinux+dtbo）原版，本地分支是 A311D 适配版。
6.3 本地 a311d 分支 libmali/mali-bifrost 对 A311D 同样设 DRIVER_VERSION=r51p0、
    MALI_PLATFORM=meson，与官方 next 的 S922X 策略一致；差异只在 gpudriver 的
    引导链适配，不在 DDK 选择。故第 5 节的 r51p0/r54p2 不配平对两者都成立。

七、libmali 在 ROCKNIX 下的完整实现链路（自构建到运行）
--------------------------------------------------------------------------------
    [构建期] libmali/package.mk
      按 DEVICE 选 DRIVER_VERSION（S922X/A311D=r51p0），按 DISPLAYSERVER 选
      -wayland-gbm；从 github.com/ROCKNIX/libmali 的 zip 只解出所需 .so/hook/
      meson/data；meson 以 -Dwrappers=enabled -Dvendor-package=true 构建包装库；
      patchelf 给 mali 库追加 libmali-hook.so.1 依赖；Vulkan lib 移出 bind 目录。
    [内核] mali-bifrost/package.mk 从 rocknix/mali_kbase 编 mali_kbase.ko
      （A311D/S922X 用 MALI_PLATFORM=meson），落入 kernel-overlays。
    [安装] gpudriver/package.mk 生成 /usr/bin/gpudriver，按设备注入 PAN 名、
      GPU_OPTIONS 与 DTB overlay 命令（A311D 分支注入空命令）。
    [启动/运行] gpudriver --start 读 gpu.driver（默认 libmali），用 modprobe
      切内核模块 + mount --bind 切用户态 GL/GBM/SDL + /dev/null 屏蔽 libGL 与
      对方 ICD；显式切换命令另写 DTB overlay 以在下次启动生效。
    [图形栈] 应用链接 /usr/lib/libEGL.so 等，经 mali 包装库 -> libmali-hook ->
      libmali.so(r51p0) -> mali_kbase.ko(r54p2) -> GPU。

九、风险与建议（不执行，仅方向）
--------------------------------------------------------------------------------
9.1 不要用 20261101 官方镜像作为 libmali 可用性依据：其 DDK 组合先天不配平。
9.2 若坚持 libmali：需为 A311D/S922X 固定与 r51p0 对齐的内核 kbase（当前上游
    无 r51p0 内核 DDK），或整体换用同版本 DDK 的用户态+内核态；见第二十六节 F1。
9.3 不改动项：gpudriver 切换逻辑（S922X 与 A311D 各自正确）、DTS、引导链、
    config.ini；避免无关重构。
9.4 当前设备建议维持 panfrost（已实测主题正常加载、fault 归零、无绿屏）。
