一、结论摘要
--------------------------------------------------------------------------------
1. 分辨率已从 3840x2160@60 改为 1920x1080@60，并已冷启动验证保持。
   持久化键：system.display_mode_hdmi=1920x1080@60Hz
   （/storage/.config/system/configs/system.cfg:231）

2. 「切换后菜单界面不是全屏」不是新的显示故障，而是操作顺序问题：
   运行时用 swaymsg 换模式时，EmulationStation 已经以 3840x2160 完成初始化，
   SDL2 客户端不会因输出模式变化重新分配缓冲区；sway 侧该节点仍标记
   fullscreen（fullscreen_mode=1），只是拿旧尺寸的画面铺在新输出上，
   于是屏幕上只看到原 4K 画面的左上角一块 —— 表现就是「菜单不在全屏、
   内容被裁切、字号反而变大」。
   重启前端/整机后，ES 在 1080p 下重新初始化，即恢复正常全屏。

3. 因此：改分辨率必须重启前端（systemctl restart essway）或整机，
   等价于 ES 菜单里改显示模式后自动重启的行为；只敲 swaymsg 只适合临时试。

三、分辨率是怎么定的（源码级）
--------------------------------------------------------------------------------
链路：
  /storage/.config/system/configs/system.cfg
      system.display_mode_hdmi=<WxH@RHz>
      ↓ get_setting（/etc/profile 内 shell 函数）
  /usr/share/autostart/111-sway-init（每次启动重写 /storage/.config/sway/config）
      DISPLAY_MODE 为空 → 不写 output mode，交给 DRM 默认（EDID 首选 4K）
      DISPLAY_MODE 非空 → sed 解析出 width/height/rr，追加
          output HDMI-A-1 mode <W>x<H>@<R>Hz
      ↓
  sway 启动时应用，ES 随后在此时序下初始化

要点：
  - /storage/.config/sway/config 每次启动被 111-sway-init 覆盖重建，
    手改该文件只在本次运行有效，不是持久化位置。
  - 持久化只认 system.cfg 的 system.display_mode_hdmi（HDMI 口优先）；
    该键不存在时回退 system.display_mode。
  - /flash/config.ini 里的 vout= 示例是注释状态且 Stage-B 的 cfgload
    硬编码 bootargs、并不读 config.ini，改它无效。
  - /proc/cmdline 里仍留着 u-boot 的 vout=1366x768p60hz、hdmimode=1366x768p60hz，
    那是 Stage-A 引导阶段的初值，与最终 DRM/HDMI 输出无关，不要据此判断当前分辨率。
  - /sys/class/graphics/fb0/virtual_size 仍是 3840,2160（meson-drm 的
    drm_fbdev 在启动时按首选模式建一次后不随模式变化重建）。它不是扫描输出路径，
    判断实际分辨率只看 sway 的 current_mode 或 KMS state 的 crtc mode。

四、执行步骤（已做，全部可回滚）
--------------------------------------------------------------------------------
1. 备份：/storage/_lang_backup/system.cfg.bak2（改前）
2. 运行时试切：swaymsg output HDMI-A-1 mode 1920x1080@60Hz
   → rect 1920x1080，current_mode 1920x1080@60000
3. 持久化：set_setting system.display_mode_hdmi "1920x1080@60Hz"
   → system.cfg:331（重启后 ES 重写文件，键移到 231，值不变）
4. 同步本次会话的 sway 配置（仅为 reload 场景）：
   echo "output HDMI-A-1 mode 1920x1080@60Hz" >> /storage/.config/sway/config
   swaymsg reload → 仍为 1920x1080@60（确认该行与生成行等价、无副作用）
5. 冷启动：systemctl reboot --no-block，81 s 后 SSH 恢复
   → 111-sway-init 自动生成 output HDMI-A-1 mode 1920x1080@60Hz
     （本次落在 /storage/.config/sway/config:5）
   → ES 在 1080p 下重启，界面满屏

解析逻辑自检（在设备上按 111-sway-init 的同一段 sed 跑一遍）：
  DM=1920x1080@60Hz → PARSED: w=1920 h=1080 rr=60
  WOULD-EMIT: output HDMI-A-1 mode 1920x1080@60Hz

五、「非全屏」的判定依据
--------------------------------------------------------------------------------
现象期（运行时切换后、重启前）：
  sway current_mode 已是 1920x1080@60，
  但 ES 节点仍是 fullscreen 状态、内容按 3840x2160 绘制；
  grim 抓到的 1920x1080 帧里只有原画面左上部分，底部提示栏整体缺失。
重启后：
  ES rect=1920x1080，与 current_mode 一致，界面满屏（截图见第二节）。
判断方法：看 ES 节点 rect 与输出 current_mode 是否一致；
不一致即「客户端未重建缓冲区」，重启前端即可，不必怀疑模式本身。

六、回滚方法
--------------------------------------------------------------------------------
改回 4K：
  set_setting system.display_mode_hdmi "3840x2160@60Hz"   （可选）
  # 或直接删掉该键，交回 EDID 首选模式：
  sed -i '/^system\.display_mode_hdmi=/d' /storage/.config/system/configs/system.cfg
然后 systemctl restart essway（或 reboot）。
临时试：swaymsg output HDMI-A-1 mode 3840x2160@60Hz（不重启前端会出现同样的
裁切现象，属正常）。

七、遗留与提醒
--------------------------------------------------------------------------------
1. 这是配置变更，不是镜像内默认值。重新刷同一镜像仍回 4K@60；
   若要「构建即 1080p」，需在镜像的默认 system.cfg 或 111-sway-init 里改默认值。
2. ES 菜单里切换显示模式是否同样生效未单独验证；从代码看走的是同一个
   system.display_mode_hdmi 键，但需注意它会写 system.cfg 并重启前端。
3. 本次切换后 EDID 未见重新读取（仍为 FFA SMART TV，首选 4K）；
   1080p 是从 EDID 已有模式表中选取，不影响兼容性。
4. fb0 报 4K 属 drm_fbdev 行为，不是故障；若后续有组件按 fb0 取分辨率，
   需要单独处理（当前 ES/sway 不读它）。

八、初始分辨率为什么是 3840x2160@60（已追到构建层）
--------------------------------------------------------------------------------
链路（每一步均有实机证据）：
  1. 镜像默认模板 /usr/config/system/configs/system.cfg（设备实测 8785 B）
     里没有任何 display_mode 键：
       grep -n "display_mode" /usr/config/system/configs/system.cfg -> rc=1
  2. 首次启动把模板 seed 成 /storage/.config/system/configs/system.cfg
     （001-functions:set_setting 中 cp -f；chksysconfig verify 在缺
      hostname/retroarch 配置时做整目录 rsync）。
  3. 111-sway-init 用 get_setting 取不到值 → 不生成 output ... mode 行。
     本次改动前设备上的 /storage/.config/sway/config 只有：
       output HDMI-A-1 transform 0 / bg #000000 solid_color /
       allow_tearing yes / max_render_time off
  4. 没有 mode 指令时 wlroots 取连接器 preferred mode。该电视 EDID
     （厂商 FFA、型号 "FFA SMART TV"）首选即 3840x2160@60：
       /sys/class/drm/card0-HDMI-A-1/modes 首项 3840x2160（共 9 条 4K 变体）
       sway get_outputs 的 modes 首项 3840x2160@60000
  → 因此"出厂默认"= EDID 首选 4K@60，不是镜像里写死的值。

补充一个容易误判的现象：
  启动早期还会短暂停在 u-boot 传下来的 1366x768（/proc/cmdline 的
  vout=1366x768p60hz，Stage-A 初值）。一旦 HDMI 重新协商/hotplug，
  wlroots 就切到 EDID 首选的 4K。
  证据：同一天两次取样，20:53 截图为 1366x768，21:16 截图为 3840x2160。
  即"初始值"取决于本次启动有没有发生 modeset，而稳态是 4K@60。

启动时序（说明为什么把默认值写进模板就能在首启生效）：
  journalctl -b -o short-monotonic
    [179.6] Starting rocknix-autostart.service...
    [209.29] Starting[1768]: sway.service essway.service...
    [209.36] Starting sway.service...
    [209.41] Finished rocknix-autostart.service.
  编号脚本（含 111-sway-init）先跑完，再由 autostart 拉起 sway/essway，
  所以模板里的 display_mode_hdmi 在第一启动就能被读到。

九、构建层修改（本次落地）
--------------------------------------------------------------------------------
文件：projects/ROCKNIX/packages/rocknix/package.mk
位置：makeinstall_target() 内既有的 if [ "${DEVICE}" = "A311D" ] 块，
      紧跟 gpu.driver=panfrost 之后：
        if grep -q '^system.display_mode_hdmi=' <模板>
        then sed -i "s#^system.display_mode_hdmi=.*#system.display_mode_hdmi=1920x1080@60Hz#"
        else echo "system.display_mode_hdmi=1920x1080@60Hz" >> <模板>
        fi
理由：与同块 gpu.driver 的写法保持一致（存在则覆盖、不存在则追加），
      作用域仅 A311D，不改公共模板，其他机型仍按 EDID 首选。

校验（本地，未重建镜像）：
  bash -n projects/ROCKNIX/packages/rocknix/package.mk        -> 通过
  复制模板到临时 INSTALL 目录，按上述逻辑跑两遍：
    第一遍 -> 追加，落在模板第 322 行
    第二遍 -> grep -c 结果仍为 1（幂等，不会重复追加）

生效范围与限制：
  - 全新刷盘：首启 /storage 为空，由模板 seed，直接 1080p60。
  - 已存在的 /storage：chksysconfig verify 只在缺 hostname/retroarch 配置时
    整目录 rsync，不会补单个新键；需手工 set_setting 一次（本机已于 21:17
    写入，现 system.cfg:231）。
  - [未执行] 完整重建 + 刷盘 + 首启复验；本轮只到源码级与本地模拟。
  - 值格式必须为 WxH@RHz：sway-init 的解析只认 "@数字Hz"（或纯数字），
    写成 1920x1080p60hz 这类形式不会生成 mode 行。ES 菜单写回的格式未验证。
